# Changelog

All notable changes to this project are documented in this file. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- **Breaking:** the column component is split by what the cell shows, so no value is typed as `object`. `KlyDataListColumn<TItem>` is replaced by `KlyDataListColumn<TItem, TValue>` (a typed `Property` expression, `SummaryValue` returning `TValue`; the row type comes from the list and the value type from the expression, so markup writes `<KlyDataListColumn Property="@(o => o.Total)" />`), `KlyDataListFieldColumn<TItem>` (`Field`, a key of the schema) and `KlyDataListTemplateColumn<TItem>` (`Template`, with a `Key` to sort, export and summarize). All derive from `KlyDataListColumnBase<TItem>`, which keeps the shared parameters (pinning, widths, format, alignment, visibility, header menu, summaries); `DataListContext<TItem>.Columns` is a list of it.
- **Breaking:** `DataListGroupBy<TItem>` is an abstract base created with `DataListGroupBy<T>.By(key, order, comparer)` or `.ByField(fieldKey)`, or with `new DataListGroupBy<T, TKey>(key) { ... }`. The `Key` and `Field` properties are gone. `DataListGroup<TItem>` is the abstract group, and `DataListGroup<TItem, TKey>` carries `Value` as a `TKey`; `Label`, `LabelTemplate`, `Summary`, `SummaryTemplate` and `DefaultCollapsed` of a typed grouping receive it. Groups of a key that is an enum, a number or a date order by value (before, by the text of the value when the type was not the same on both sides).
- **Breaking:** summaries no longer pass `object`. `DataListSummaries<T>.ResolveAsync` returns `IReadOnlyDictionary<string, DataListSummaryValue>`, and `DataListSummaryCellContext.Value` is a `DataListSummaryValue`: a struct that holds a number (formatted by the column) or a text, converted implicitly from `decimal`, integers and `string`. A summary over text or dates adds up to 0 (`Sum`) or nothing (`Average`): only numeric values add up, where a numeric string used to be summed.
- The table reads fields through `DataListSchema<T>.FormatField`, `TryReadNumber` and `CompareField` of Klyroo.Query (which no longer has `ReadField`), and the CSV export decides the formula guard from the type of the column, not from a boxed value.
- The Tailwind integration now reaches apps: `buildTransitive/Klyroo.Table.targets` was not packed (and its old name, `Klyroo.UI.Tools.targets`, is not one NuGet imports), and it copied the class list under a name the Klyroo.UI Tailwind entry does not import. With `KlyrooTailwind` on, the table classes are now generated with no manual step, and `KLYTOOLS001` warns a project that references the package without Tailwind.
- The filter editor names the type of the Klyroo.UI inputs it binds (`KlyInputNumber<decimal?>`, `KlySlider<double>`, `KlyInputDate<DateOnly?>`), which are generic since Klyroo.UI binds to the type of the model property: a `ValueChanged` that is a method group cannot be typed by inference. Nothing changes for the data list.
- The prerender persistence of a data list is counted as sent, with the escaping and the two base64 encodings Blazor adds, and draws on the budget every Klyroo library of the page shares (`KlyrooOptions.PersistedStateMaxBytes`, 28 KB). Before, the lists of a page counted raw JSON against their own 8 KB budget, so a page with a dashboard could pass SignalR's 32 KB message limit and fail to start its circuit. `PersistMaxBytes` now counts sent bytes (24 KB by default), and `PersistPageMaxBytes` is removed. Column preferences handed over by the prerender count in the same budget.

### Fixed

- CSV export: only numbers, `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly`, `TimeSpan`, `Guid` and `bool` skip the formula guard (before, any `IFormattable`, enums and custom types included); a column with a template exports the `Format`-formatted value of its `Property`, or of the schema field its `Key` names; `KlyDataListExport.MaxRows` (100,000) refuses a bigger export with a message and a `DataListExportTooLargeException`; and the file reaches the browser as a `DotNetStreamReference` instead of one string (`klyroo-table-download.js` now exports `downloadStream`).
- The row click is decided in the browser: only a real activation of a row (not a click on a control inside it, nor in the padding of the selection, detail and actions cells, nor a key typed in a field) is sent to .NET, through one custom event `klyrowactivate` that replaces `klyrowclick` and `klyrowkey`. `KlyRowEventArgs.Ignore` is removed. `Klyroo.Table.lib.module.js` guards the event registration so that loading the module twice does not throw, and now carries a header saying it is maintained by hand; tests for it run with `node --test tests/js/*.test.mjs`.
- A detail row opened in a table whose schema has no `RowKey` (or whose keys repeat) no longer shows up open on another row after a page, sort or filter change: the open state kept by place on the page is dropped when new rows arrive, while the state kept by row key stays.
- A plain click on a sort column that is in a multi-column sort but not first makes it the only sort, ascending. Before, its next step could leave a sort on neither column.

### Added

- Guide: edit a row through a row action that opens a Klyroo.Form drawer or a Klyroo.UI modal and updates the list with `UpdateRow` or `RefreshAsync`, with the table staying read-only.
- CSV export: `KlyDataListExport` is a button (a menu with this page, the selection and every result when several apply) that downloads the visible columns in the user's order, formatted with their `Format` and the culture of the page. `DataListCsv` and `DataListCsvOptions` (in `Klyroo.Table.Core`) write RFC 4180 CSV with a `;` delimiter for decimal-comma cultures, a UTF-8 byte order mark (on by default, `Utf8Bom = false` turns it off), and an apostrophe in front of text cells that start with `=`, `+`, `-`, `@`, a tab or a carriage return. `LoadAll` exports every result of a provider or queryable list, `OnExport` receives the file instead of the browser download (for MAUI or an upload), and `DataListContext` gains `ExportRows`, `ExportHeaders`, `ToCsv`, `ExportCsv` and `HoldsAllRows`. New `klyroo-table-download.js` module.
- Master-detail: `KlyDataListTable.DetailTemplate` draws a full-width detail row under each row, opened by a button in a new first column (`aria-expanded`, `aria-controls`, an accessible name with the row label, ArrowRight and ArrowLeft). It uses the existing row expansion state (`DataListContext.IsRowExpanded`, `SetRowExpanded`, `ExpandAll`, `CollapseAll`, `ExpandedKeys`), which now works without a `Tree`, and `DataListContext.HasDetail` says whether a table has one. Not supported with `Virtualize` or `Tree` (the detail is ignored).
- Multi-column sort in the table: Shift+click on a sortable header appends the column to the sort, cycles it ascending, descending and out while keeping the other sorts, and a plain click keeps one sort as before. Headers show the place of each column (1, 2, 3) while several sorts are active, `aria-sort` stays on the first, and `KlyDataListSortMenu` gains `Multiple` (automatic by default) to edit the list: reverse, move, remove and add. New `DataListContext` methods `NextSort(state, key, append)`, `AddSort`, `RemoveSort`, `ReverseSort`, `MoveSort` and `SortIndex`; `SortDescending(key)` now reads any position of the sort, not only the first.
- Row hooks on `KlyDataListTable`: `RowHref` (an accessible link stretched over the row, also in a static render, with the controls inside the row kept above it), `OnRowClick` (a `DataListRowClickArgs<TItem>` with the row and the modifier keys; Enter and Space activate a focused row, and clicks on controls inside the row or that end a text selection are ignored), `RowClass` and `RowAttributes`, plus `CellClass` on `KlyDataListColumn`. The click filter runs in the browser through two new custom events (`klyrowclick`, `klyrowkey`) that `Klyroo.Table.lib.module.js` registers.
- Remembered filters: `KlyDataList` now honors `DataListFilter.WithPersist()`. A change of such a filter is stored in `localStorage` (key scoped by row type, `PersistKey` or `UrlKey` and filter key, value in the URL form of `DataListStateQuery`) through the new `klyroo-table-storage.js` module; clearing the filter removes the entry, and the first interactive render, like any later navigation to the page whose address does not name a marked filter (a menu link, Back), restores its value, then writes it to the address. A filter cleared in the list stays cleared. Static renders and prerenders never touch storage, and every storage call is guarded.
- Tests for the summary scopes (`Filtered`, `Page`, `Selection`), the default sticky position of the selection bar and `DataListController.PagesLoaded` across appends, refreshes, new loads and failed appends.

## [0.1.0-preview.1] - 2026-11-24

### Added

- `KlyDataList<TItem>` data list that loads rows from in-memory `Items`, a database `Queryable` run by a replaceable `IDataListQueryExecutor`, or an asynchronous `Provider`, and keeps search, filters, sort, page, page size and layout in the query string.
- Composable parts for the list: table, card grid, search, refresh, result count, filter tags, add and clear filter buttons, filter panel, sort menu, layout switch, column panel, error and empty states, numbered pagination and a cursor-based infinite loader.
- Table features: sortable columns with a header menu, pinned and resizable columns with saved preferences, virtualized rows, collapsible row groups, footer summaries (sum, average, count, min, max), compact summary rows for phones and per-column templates.
- Selection with a bulk action bar that can target every result of a query, per-row actions with confirmation dialogs and a toolbar actions menu.
- `DataListTree<TItem>` in `Klyroo.Table.Core`: a UI-free, NativeAOT-compatible tree model that flattens rows carrying their children into nodes with depth and rail information, with expansion and selection settings for the table.
- Prerender hand-over (`ResultJson`) so an interactive list adopts the result of its prerender, and a time zone aware render for date filters in static, prerendered and interactive modes.
- Twelve message tables (English and French reviewed), per-instance and global theming through `DataListUi` and `KlyrooTableOptions`, and `AddKlyrooTable()` registration.
